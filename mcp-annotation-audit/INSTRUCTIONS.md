# Γενικές οδηγίες – Annotation Audit

Ισχύουν για **όλα τα projects**. Ανά project υπάρχουν μόνο τα **audit_rules.md** (και προαιρετικά project-specific σημειώσεις στο instructions.txt του project).

---

## Όταν ζητηθεί «βγάλε το report» (ή «βγάλε το report για [tab/project]»)

**Παγιωμένη αρχική έξοδος:** Να παράγεις **πάντα** report σε **Markdown (.md)** με **μόνο τα πιο σημαντικά προβλήματα** (όχι ανακοινωθέντα, όχι πλήρεις πίνακες Brand μόνο / Location μόνο). **Επίσης** να τα δείχνεις **και εδώ στο chat**: (1) τον πίνακα με τις μεγάλες αποκλίσεις (ίδιος με αυτόν στο .md), (2) από κάτω **με λόγια** μια σύντομη εξήγηση των πιο σημαντικών προβλημάτων (τι να ελέγξει πρώτα και γιατί). Μετά ο χρήστης μπορεί να ρωτήσει επιμέρους αν χρειάζεται.

### 1) Brands / Locations που λείπουν

- Από το **.txt** expected brands του project (κλήση `annotation_list_brands_files` + `annotation_find_missing_brands`, ή αν `brands_files: []` διάβασε το .txt από workspace `mcp-annotation-audit/projects/<project>/`).
- Εφάρμοσε **audit_rules.md** (team-specific, alcohol σε muslim-country).
- Στο report: **μόνο** ποια brands (ή locations) λείπουν· αν δεν λείπει τίποτα, γράψε «Κανένα» και πλήθος γραμμών με κενό Brand (αν 0, πες 0). **Μην** βάζεις πλήρη λίστα expected brands ούτε μακριά εξηγήσεις για το MCP.

### 2) Μεγάλες αποκλίσεις (duration)

**Πάντα merge Part1 + Part2** ανά αγώνα (match_id από File χωρίς `_Part1`/`_Part2`).

- Στο report να δείχνεις **μόνο μεγάλες αποκλίσεις**: πίνακας **Brand · Location** με duration ανά αγώνα και **Δ (sec)** = max − min. Να συμπεριλαμβάνονται μόνο συνδυασμοί με **μεγάλο Δ** (π.χ. Δ ≥ 400 ή τα top N), ταξινόμηση κατά φθίνουσα Δ.
- **Μην** βάζεις ξεχωριστά τμήματα «Brand μόνο» ή «Location μόνο»· μόνο ο πίνακας Brand · Location με τις μεγαλύτερες αποκλίσεις και μία σύντομη προτεραιότητα review.

---

## Match ID – Part1 / Part2

Όταν το **File** έχει το ίδιο id με διαφορετικό Part (Part1 vs Part2), είναι **ίδιος αγώνας**: πρέπει πάντα να **ενώνεις** τα results.  
Εξαγωγή match_id από File (αγνόησε `_Part1` / `_Part2` στο τέλος). Για κάθε (match_id, Brand, Location) άθροισε Total Duration από όλες τις γραμμές. Σε όλες τις αναλύσεις ανά αγώνα χρησιμοποίησε αυτό το merged view.

## Τεχνικά

- Όταν ο χρήστης ζητά **ρητά** ένα tab/project (π.χ. «για ICC_Rest») ή δίνει **URL με gid** (π.χ. `#gid=395374545`), να καλείς **πρώτα** `annotation_use_project(project="ICC_Rest", sheet_gid="395374545")` (project = folder name, sheet_gid = αριθμός από το URL). Το **sheet_gid** ανοίγει το worksheet **από ID**, ώστε να διαβαστεί το σωστό tab ακόμα κι αν το όνομα του tab διαφέρει.
- Να χρησιμοποιείς τα **MCP tools** και να κάνεις εσύ την ανάλυση/υπολογισμούς (**δεν γράφουμε scripts**).  
- Νέο ή καλύτερο tool να προτείνεις **μόνο** αν κάτι είναι πραγματικά πολύ δύσκολο, και τότε να εξηγείς γιατί και να ζητάς έγκριση.
